# 本地验收清单

本清单用于在本地验收「Go + SQLite 后端 + 原 Vue 前端」版本。默认不需要推送 GitHub，也不需要触发 Actions。

## 1. 环境准备

- Node.js 18+ 与 npm
- Go 1.22+
- Docker Desktop（可选，用于容器方式运行）

Windows PowerShell 若禁止 `npm.ps1`，使用 `npm.cmd`。

## 2. 启动方式

### 方式 A：开发模式（前后端分别启动）

```bash
# 终端 1
cd backend
go run ./cmd/server

# 终端 2（仓库根目录）
npm ci
npm run dev
```

打开 <http://localhost:5173>。前端 `/api` 会代理到 `http://127.0.0.1:8080`。

### 方式 B：Docker Compose

```bash
docker compose up --build -d
docker compose ps          # 应显示 healthy
```

打开 <http://localhost:8080>。数据库文件在 `./data/onestar.db`。

## 3. 基础可用性

- [ ] 页面正常加载，侧边栏菜单完整（经营看板、商品中心、订单中心、收入记录、自动定价、支出记录、扫码出入库、研究所、灵感生成、印章生成、内页生成器、胶带生成、数据中心）。
- [ ] 浏览器控制台无红色报错；刷新后数据仍在。
- [ ] `curl http://127.0.0.1:8080/api/v1/health` 返回 `{"status":"ok",...}`。
- [ ] 数据中心显示「服务端存储 · 已启用」，不再是「云端同步 即将推出」。

## 4. 核心业务

### 商品与 SKU

- [ ] 商品中心新增商品，SKU 留空能自动生成（形如 `1-0001`），重复添加不冲突。
- [ ] 商品列表、编辑、删除正常；库存低于安全库存时有低库存提示。

### 订单与库存

- [ ] 新建订单后，订单列表出现记录，金额、平台费、货款、净利润与手算一致。
- [ ] 下单后商品库存减少；删除订单后库存回补。
- [ ] 编辑订单后总金额与库存随之更新。

### 支出与收入

- [ ] 支出记录新增/编辑/删除正常。
- [ ] 收入记录新增一场集市（名称、日期、地点、收入），汇总卡片同步变化。
- [ ] 保存线上收入后，总收入 = 集市合计 + 线上收入，利润 = 总收入 − 支出合计。
- [ ] 制造「支出 > 收入」的情况，利润变红、出现红色提醒条，顶部徽章也变红。

### 研究所与灵感

- [ ] 新建研发项目，修改阶段后进度变化。
- [ ] 追加打样记录，转正式商品后商品中心出现 `LAB-<id>` 商品。
- [ ] 灵感生成页可以新增与删除记录。

### 内页生成器与胶带

- [ ] 内页生成器切换 M5/A7/A6 等尺寸，预览比例正确；模块可增删、调权重与颜色。
- [ ] 保存模板后刷新页面，「我的模板」仍能载入该模板。
- [ ] 打印预览的纸张尺寸与所选毫米数一致（浏览器打印对话框边距选「无」）。
- [ ] 胶带生成页可调整宽长、叠加图案层、修改排数/列数/大小/颜色，预览实时更新。
- [ ] 导出 PNG 尺寸正确；导出 PSD 能在 Photoshop 中打开并看到分层。

### 数据中心

- [ ] 导出备份得到 `onestarlab-backup.json`。
- [ ] 修改一些数据后导入刚才的备份，数据回到导出时的状态。
- [ ] 导入非法 JSON 时提示错误且现有数据不被清空。

## 5. 持久化与容器

- [ ] 开发模式重启 `go run ./cmd/server` 后，数据仍在 `backend/data/onestar.db`。
- [ ] 容器模式执行 `docker compose restart` 后数据仍在。
- [ ] `docker compose down` 再 `docker compose up -d` 后数据仍在（`./data` 为 bind mount）。
- [ ] `docker compose logs` 中能看到 `GET /api/v1/bootstrap 200` 与静态资源请求。

## 6. 重置本地数据

开发模式：

```bash
# 停止后端后删除数据库文件
rm backend/data/onestar.db
cd backend && go run ./cmd/server
```

容器模式：

```bash
docker compose down
rm data/onestar.db
docker compose up -d
```

重新启动后会自动建表并写入默认分类与默认定价规则。

## 7. 已知限制（验收时请留意）

- 浏览器里旧版（纯前端 IndexedDB）的数据不会自动迁移到 SQLite；旧版导出的 Dexie 备份文件也不能直接导入新版。需要迁移时请单独处理。
- 默认没有账号体系；若服务暴露到局域网/公网，请设置 `API_TOKEN`，或只在可信网络内使用。
- 没有实时推送：多个标签页/设备同时修改时，需要刷新才能看到对方的最新数据。
- 单实例单 SQLite 文件，适合单店使用；不支持多节点同时写同一个库。
- 扫码摄像头需要 HTTPS 或 `localhost`；通过局域网 IP 访问时浏览器不会授予相机权限。
- M2.5 等超小内页需要先在操作系统里建立自定义纸张，否则打印可能回退到 A4。
